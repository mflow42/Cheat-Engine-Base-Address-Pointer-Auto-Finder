# Cheat Engine Base Address Pointer Auto Finder

[English](README.md) | **Русский**

**Pointer Finder** — универсальный Lua-инструмент, поставляемый одним файлом
таблицы Cheat Engine (`PointerFinder.CT`). Он автоматически находит
**базовый адрес** — привязанную к модулю цепочку указателей вида
`game.exe+9080` → `+10` → `+10` → `+10` → `+0` — для любого значения,
найденного сканером CE, и добавляет готовую Pointer-запись в адресный лист.

> Инструмент предназначен для **одиночных (offline) игр** и обучения.
> Использование редакторов памяти в онлайн-играх обычно нарушает правила
> и античит-системы. Используйте на свой риск.

## Зачем

В играх с GC (garbage collector — сборщик мусора) или переездами аллокаций найденный сканом адрес умирает за
секунды. Ручная рутина — «find what writes → кто указывает на объект писца →
и так до статики» — долгая и ошибкоёмкая. Pointer Finder автоматизирует весь
подъём, а если всё рушится посреди поиска (GC переставил узлы, адрес оказался
мёртвой стековой копией, цепочка оказалась ложной) — **восстанавливается сам**,
не требуя начать заново.

## Быстрый старт

1. Запустите игру, подключите CE.
2. Откройте `PointerFinder.CT` — появится окно инструмента. (После обновления
   без переоткрытия CE: Lua Engine (Ctrl+Alt+L) → `abfReload()` → Execute.)
3. Найдите значение сканом CE (деньги — обычно Double), вставьте адрес в окно
   инструмента, нажмите **Старт**.
4. Играйте — триггерьте изменение значения. **Практическое правило: раз в
   5–10 секунд — этого достаточно.** Чаще не нужно: инструменту хватает
   одного тика на подъём или проверку кандидата, а короткая пауза между
   изменениями даёт значению «устаканиться» перед контрольным чтением.
   А хорошая стратегия и вовсе такая: **спровоцируйте изменение один раз
   и просто ждите** — обычно инструмент сам поднимается по
   всей цепочке и проверяет указатель, дополнительные триггеры не нужны.
5. Ждите `BASE ADDRESS FOUND` (интерфейс и лог инструмента — на английском).
   Pointer-запись добавляется в адресный лист сразу с именем
   `Pointer Finder (120s check): …` — первые две минуты инструмент
   перепроверяет цепочку по живому значению; если она держится, запись
   переименовывается в финальную `Pointer Finder: …` (чёрным). Цепочка,
   переставшая следовать за значением, сохраняется с пометкой
   `Pointer Finder (WRONG?): …` (серым) — можно перепроверить вручную.

Подходит **любой** адрес из скана — даже мёртвый:

- **Стековая копия?** Инструмент использует её только как датчик изменений
  и сканирует память по настоящему хранилищу сразу после следующего изменения
  значения (режим свежего скана).
- **Адрес умер посреди поиска?** Вотчдог переищет живые копии значения
  и продолжит с них.
- **Цепочка правдоподобная, но читает не то значение?** Каждая цепочка
  сверяется с *текущим* значением до принятия; ложные отбраковываются,
  поиск продолжается.

## Что получите

Одна Pointer-запись, привязанная к модулю:

```
Description: Pointer Finder: [[[[[target_game.exe+9080]+10]+10]+10]+0]
Address:     target_game.exe+9080
Offsets:     0, 10, 10, 10
Type:        Double
```

Запись самопроверяется пошагово (адрес и значение), проверка печатается
в лог. Запасная запись на «сыром» адресе создаётся только если ваша сборка
CE не вычисляет модульные выражения.

**Логи** (пригодятся при обращении): каждое нажатие **Старт** создаёт свежий
`pointerfinder_log_ГГГГ-ММ-ДД_ЧЧММСС.txt` в папке `%TEMP%` — открыть:
`Win+R` → `%TEMP%`. Рядом лежит `PointerFinder_selfcheck.txt` (дамп проверки
цепочки). Отвергнутые цепочки остаются в адресном листе с пометкой
`(WRONG?)` — можно перепроверить их вручную.

## Как это работает

1. На введённый адрес ставится write-watchpoint на debug-регистрах
   (классическое «find what writes»); уровни выше — access-watchpoints,
   потому что ячейки-держатели *читаются* каждый кадр и редко пишутся.
2. Из инструкции писца восстанавливается объект-владелец поля — включая
   случай `mov rax,[rax+10]` (обход списка), когда базовый регистр
   перезагружается самой инструкцией.
3. Скан памяти на указатели на объект находит ячейку-держатель уровнем выше.
   Повтор, пока держатель не окажется статикой внутри модуля игры.
4. Цепочка сверяется с живым значением (с исходного адреса), затем
   сохраняется как Pointer-запись CE.

Поиск идёт короткими окнами (игра остаётся играбельной) и самовосстанавливается
после перестроек GC, мёртвых адресов и нехватки watchpoint-бюджета.

## Типы значений

Любой числовой тип CE: **Byte, 2 Bytes, 4 Bytes, 8 Bytes, Float, Double**,
а также **Custom** (1–8 байт, выбирается рядом с типом). По умолчанию —
Double, для денег/валюты это почти всегда правильный выбор.

## Требования

- Cheat Engine **7.4+** (проверено на 7.7), игры x64
- Таблица самодостаточна: весь код встроен в .CT

## Известные ограничения

Инструмент находит цепочку, только если она **существует**: каждый уровень
цепочки — это указатель, лежащий в памяти, а заканчивается цепочка статическим
адресом внутри модуля игры (`game.exe+offset`). Два случая, когда это не так:

- **Игры на .NET / Mono** (например, Hades): статические «глобальные» значения
  живут в памяти рантайма, а не в образе исполняемого файла — якоря вида
  `game.exe+offset` не существует. Вместо этого используйте Mono-возможности
  Cheat Engine (Mono → Dissect mono structures) для доступа к статическим
  полям.
- **Объекты, хранимые без указателей** (таблицы хэндлов, адрес вычисляется из
  хэша/ID): инструмент ищет реальные ссылки-указатели; если на объект
  хранилища не указывает ни одна ячейка памяти, цепочку собрать не из чего —
  это свойство игры, а не сбой поиска.

В обоих случаях ручной pointer-scan в CE выдаст столько же — то есть ничего.

Ещё одна переменная — **ваша система, а не игра**, и вот честный случай из
разработки. С установленным Kaspersky привязка отладчика могла зависать
намертво (вылечилось удалением антивируса). Аппаратные read-watchpoints в
какой-то момент перестали доставляться целиком — и это пережило удаление
антивируса, перезагрузку и выключение Hyper-V, так что причину до конца
установить не удалось. Pointer Finder v2.10 от read-watchpoints не зависит:
поиск переключается на статические сканы указателей, и инструмент проверенно
работал именно в таком деградировавшем режиме. Практический совет: добавьте
Cheat Engine в доверенные вашего антивируса (вернёт быструю привязку и
ловушки), а строка статуса и лог подскажут, какой режим у вас сейчас.

## Сборка таблицы

`PointerFinder.CT` генерируется из `pointerfinder.lua`:

```
python make_ct.py          # соберёт PointerFinder.CT (код встраивается)
python make_ct.py --dev    # ещё и PointerFinder-dev.CT (грузит .lua из папки;
                           # локальный артефакт для разработки, в git не входит)
python lua_check.py        # компиляция pointerfinder.lua настоящим Lua 5.3 из CE
```

`lua_check.py` ищет `lua53-64.dll` CE в стандартных местах; если CE стоит
в другом месте — задайте переменную окружения `CE_DIR`.

## Демо-мишень (`testtarget/`)

В `testtarget/` — маленькая «фейковая игра» с 5-уровневой цепочкой, где
**каждый уровень показывает своё число**: удобно проверять и инструмент,
и свою сборку CE. См. [testtarget/README.md](testtarget/README.md).

## Lua API

Глобальные функции (удобно для автоматизации): `abfReload()`, `abfStart(addr,
typeName)`, `abfStatus()`, `abfStop()`.
